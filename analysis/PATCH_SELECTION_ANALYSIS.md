# Patch Selection 동작 분석 (작업3 + 작업4)

## 1. 개요

이 문서의 목적은 `best_patch_selection.pth`가 실제 추론 시 **궤적(history
viewport trajectory)에 반응해서 동적으로 patch를 선택**하는지, 아니면
**입력과 무관하게 고정된 패턴으로 collapse**했는지를 데이터로 검증하는 것이다.
작업3(선택 빈도 heatmap)과 작업4(궤적-patch 관계 분석) 두 세션의 결과를
합쳐서 정리한다.

**데이터**: `config.py`의 공식 held-out **test split** (Jin2022,
`video=[4, 8, 14, 18, 24, 25]`, user 21명, `his_window=10`/`fut_window=20`/
`step=15` 기본값) 전량 **1698개 샘플**.

**선택 기준**: `run_plm.py` CLI에서 `--patch-top-k`/`--patch-threshold`를
지정하지 않는 현재 기본 실행 방식을 그대로 재현 — `select_patches(top_k=None,
threshold=None)` → 코드 기본값인 **threshold=0.5**, 선택 0개일 때 top-1 강제
포함하는 파이프라인 safety fallback(`pipeline.py:325-326`)도 동일 적용.

## 2. 데이터 신뢰성 확인

분석을 시작하기 전, `analysis/` 폴더에 이미 존재하던 `patch_selection_dataset.pkl`
(레코드 1698개, `selected_patches`까지 계산되어 있던 파일)을 사용할 수 있는지
검증했다.

- history/video/user/timestep은 현재 `create_dataset('Jin2022', include=('test',))`
  결과와 **100% 일치**했다.
- 하지만 그 pkl의 `logits`를 현재 `best_patch_selection.pth`로 재계산한
  logit과 비교하면, 샘플 20개 평균 **상관계수 0.86, exact match 0%**로
  불일치했다.

즉 입력 데이터는 같지만 모델 출력이 다르다는 뜻이므로, 그 pkl은 **현재와 다른
(아마도 이후 재학습으로 덮어써지기 전의) 체크포인트로 생성된 것**으로 추정된다.
신뢰할 수 없다고 판단해 사용하지 않았고, `best_patch_selection.pth`를 새로
로드해 전체 파이프라인(추론 → `select_patches()`)을 처음부터 재실행해서
데이터를 재생성했다.

## 3. Patch 선택 빈도 (작업3)

전체 1698개 테스트 샘플에 대해 `select_patches()`를 그대로 호출해 16개 grid
위치(4×4)별 선택 빈도를 집계했다.

### 선택 빈도표 (상위 4개 + 하위 2개)

| 순위 | patch | (row, col) | 선택 빈도 |
|---|---|---|---|
| 1위 | 6 | (1, 2) — 수평선, yaw 0~90° | **99.47%** |
| 2위 | 11 | (2, 3) — 수평선, yaw 90~180° | 91.28% |
| 3위 | 10 | (2, 2) — 수평선, yaw 0~90° | 90.40% |
| 4위 | 7 | (1, 3) — 수평선, yaw 90~180° | 90.16% |
| ... | | | |
| 하위 2위 | 0 | (0, 0) — 상단 극지방 | 1.47% |
| 하위 1위 | 1 | (0, 1) — 상단 극지방 | **0.00%** (한 번도 선택 안 됨) |

전체 16개 patch의 빈도표는 `patch_selection_frequency.json`에 있다.

### 시각화

- `patch_selection_heatmap.png` — grid 좌표 기준 heatmap
- `patch_selection_heatmap_overlay.png` — 실제 프레임(video4) 위에 겹친 버전

### 패턴

- **수평선 밴드(row 1-2) vs 극지방(row 0, 3) 극단적 편중**: 수평선 4칸(6,7,10,11)은
  90~99% 선택되는 반면 극지방 4칸(0,1,12,13)은 0~5%만 선택됨. 360도 영상
  시청자가 상하 극단을 거의 안 보고 수평선 근처를 본다는 잘 알려진 시청
  패턴과 일치하는, 타당한 학습 결과로 보인다.
- **좌우(yaw) 비대칭**: 같은 수평선 밴드 안에서도 yaw 0~180°(오른쪽/후방)
  쪽이 yaw -180~0°(왼쪽) 쪽보다 일관되게 높다. top-1(가장 강하게 추천된
  patch)만 봐도 **patch 7이 테스트 영상 6개 전체에서 40~50%로 1위**였다.
  6개 영상 전체에 걸친 일관된 경향이라는 점에서, 특정 사용자 몇 명의 취향이
  아니라 **Jin2022 데이터셋 자체의 콘텐츠 배치가 특정 yaw 방향에 흥미
  요소를 더 많이 두었을 가능성**을 시사한다. 다만 이는 가설 수준이며, 실제
  영상 콘텐츠를 직접 확인해 검증하지는 않았다.

## 4. 궤적 반응성 검증 (작업4)

### 핵심 질문

작업3에서 확인한 수평선 밴드 4칸(6,7,10,11)의 90~99% 압도적 선택 빈도가,
**궤적에 반응해서 동적으로 나온 결과인지, 아니면 사실상 고정 출력으로
수렴(collapse)한 것인지** 구분이 안 되는 상태였다. 이를 확인하기 위해
"같은 영상 안에서 궤적이 다른 사용자/시점들 사이에, 선택되는 patch가
유의미하게 달라지는가?"를 정량적으로 측정했다.

### Jaccard 유사도 (궤적 간 분산)

영상별로 모든 샘플 쌍의 선택 patch set에 대해 pairwise Jaccard 유사도를
계산하고, 같은 user(다른 timestep) 쌍과 다른 user 쌍으로 나누어 비교했다.

| video | same-user Jaccard | cross-user Jaccard | overall | 고유 선택 조합 수 (n=294 기준) |
|---|---|---|---|---|
| 4 | 0.682 | 0.592 | 0.596 | 47 |
| 8 | 0.614 | 0.513 | 0.517 | 52 |
| 14 | 0.619 | 0.554 | 0.557 | 42 |
| 18 | 0.632 | 0.533 | 0.538 | 51 (n=228) |
| 24 | 0.605 | 0.542 | 0.545 | 40 |
| 25 | 0.608 | 0.520 | 0.524 | 51 |

- **same-user Jaccard 범위 0.605~0.682**, **cross-user Jaccard 범위
  0.513~0.592** — **전 영상에서 일관되게 same-user가 cross-user보다 높다**.
  즉 같은 사용자의 시점 간 선택이 서로 다른 사용자 간 선택보다 더
  일관적이라는 뜻이며, 이는 사용자 간 실제 궤적 차이가 선택 차이로
  이어진다는 근거다.
- 완전히 동일한 선택이 반복됐다면 Jaccard가 1.0에 가까워야 하는데, 전체
  평균은 **0.546**으로 그와는 거리가 멀다.
- 가장 흔한(modal) 선택 조합조차 영상별 **12.6~24.5%만 차지**(평균
  18.7%) — "항상 똑같은 8개"였다면 90%+ 이어야 한다.

### 위치 인지 및 속도 반응

- **현재 위치(history 마지막 시점) patch의 포함률: 92.99%** — 모델이 현재
  위치를 인지하고 그 patch를 거의 항상 포함시킴을 확인.
- **이동 속도와 선택 patch 개수가 강하게 상관** (r=0.55): 정지(speed
  quintile 최하위 20%) 평균 4.91개 → 최고속 20% 평균 9.10개로 단조 증가.
  빠르게 움직일수록 "혹시 몰라서" 더 많은 patch를 후보로 남기는 뚜렷한
  동적 반응이다. (정지 임계값은 데이터 기반: 전체 샘플 속도 분포의 하위
  33퍼센타일 ≈ 0.91°/step)

### 방향 반응 (약함)

이동 중인 샘플에서 "현재 위치 기준 이동 방향 쪽 인접 patch(ahead)"와
"반대쪽 인접 patch(behind)"의 선택률을 비교했다.

| 축 | ahead 선택률 | behind 선택률 | n |
|---|---|---|---|
| 수평 이동만 (좌/우) | 90.70% | 94.64% | 989 |
| 수직 이동만 (상/하) | **68.24%** | 94.11% | 148 |
| 전체 | 87.77% | 94.11% | 1137 |

**ahead가 behind보다 낮다** — 특히 수직 이동에서 그 격차가 크다(68.2% vs
94.1%). 이는 모델이 "향할 방향"을 앞서 반영해 선택 범위를 넓히기보다는,
**"지나온 위치"를 계속 유지하려는 관성(hysteresis)** 쪽에 가깝다는 뜻이다.
수직 이동의 낮은 ahead 비율은 poles(row 0/3)를 향해 이동할 때 그쪽이
정적으로 거의 배제되는 patch이기 때문일 가능성이 크다(아래 참고). 즉
"미래 위치를 예측해서 선점"하는 능력의 증거는 이 데이터에서 확인되지
않았다.

### 정적 배제

영상별로 극지방(0,1,12,13 등) 4~7개 patch는 궤적과 무관하게 <5%/>95%로
사실상 고정되어 있다 (작업3의 극지방 배제 패턴과 일치). 이 부분은 궤적
반응이 아니라 학습된 정적 우선순위로 보인다.

### 대표 케이스 시각화

`patch_selection_case_studies.png` — 같은 영상(video 14) 안에서 정지 /
빠른 우측 이동 / 빠른 좌측 이동 / 빠른 하강, 4개 대표 샘플의 궤적(화살표)과
선택된 patch(파란 강조, 주황 테두리 = 현재 위치)를 나란히 비교. 각 케이스에서
선택 patch 개수와 조합이 실제로 다르게 나옴을 시각적으로 확인할 수 있다.

## 5. 방법론 노트 (검증 이력)

분석 도중 궤적 "이동 방향(direction)" 계산의 초기 버전에 버그가 있었다.
`wrap180(끝 - 시작)`(최단 각도 경로) 방식을 썼는데, history 윈도우 내
누적 회전이 180°를 넘는 빠른 궤적에서 **부호가 반전되는 문제**였다
(예: 실제로는 계속 왼쪽으로 209° 회전했는데 최단경로 계산으로는 "오른쪽
151°"로 잘못 분류됨). 케이스 스터디용 대표 샘플을 직접 검증하다가 발견했고,
누적 스텝 합산 방식(`dyaw_steps.sum(axis=1)`)으로 수정했다.

버그가 각 결과에 미친 영향을 결과별로 명시하면:

| 결과 | 버그 영향 | 최종 수치 상태 |
|---|---|---|
| Jaccard 유사도 | **없음** — `selected_patches` 마스크만 사용, direction 라벨 미사용 | 수정 전/후 동일 |
| 속도-선택개수 상관관계 (r=0.55) | **없음** — `mean_speed`/`num_selected`만 사용 | 수정 전/후 동일 |
| still/left/right/up/down 분류 | 있음 | 재검증 결과 전체 1137개 이동 샘플 중 **1개만 라벨 변경**, 집계에 미치는 영향 무시 가능 |
| ahead/behind 선택률 | 있음 (direction에 의존) | 수정 후 pkl로 재계산해 수치 변화 없음(소수점 둘째자리까지 동일) 확인 |
| 케이스 스터디 시각화 | 있음 | 버그 수정 후 재생성하여 최종본으로 교체 (샘플 2개 교체 + 화살표를 순간 이동량이 아닌 누적 net displacement 기준으로 수정) |

**결론: 이 문서에 보고된 모든 최종 수치는 버그와 무관하게 유효하다.**

## 6. 최종 결론

- **Collapse 아님** — 궤적(특히 history 내 사용자별 패턴, 이동 속도)에
  실질적으로 반응하는 동적 선택이 이루어지고 있다. Jaccard 유사도가
  1.0과 거리가 멀고(평균 0.546), 영상당 40~52종의 서로 다른 선택 조합이
  나오며, same-user 유사도가 cross-user보다 전 영상에서 일관되게
  높다는 점이 근거다.
- 다만 **완전한 미래 예측형 동적 선택도 아니다** — "현재 위치 인지 + 속도
  기반 탐색 범위 조정(hedging) + 관성(behind 우세)"의 조합이며, "향할
  방향"을 앞서 포함하는 anticipation 능력은 약하거나 없다.
- **극지방 배제는 궤적과 무관한 정적 사전지식**으로 얹혀 있다 (4~7개
  patch가 항상/거의 항상 제외됨).
- 종합하면, 이 모듈은 **"학습된 동적 선택" 위에 "학습된 정적
  우선순위"가 결합된 하이브리드 구조**로 보는 것이 가장 정확하다.
